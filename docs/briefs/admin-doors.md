# בריף 8: /admin, הדלתות

**מי:** Opus 5.5. **תלוי ב:** בריף 1. אם בריף 6 כבר בוצע, הבוט כבר נותן `/doors`; הבריף הזה מוסיף את הממשק באתר ואת האישור של חותמות.

## מטרה
עמוד `/admin` קטן, כניסה בקישור קסם למייל של דוד בלבד. שני דברים: מצב דלת לכל חדר (פתוח / נעול / בקרוב, שלט, תנאי פתיחה), ואישור או דחייה של חותמות ממתינות.

## קבצים שמותר לגעת בהם
- `app/admin/page.tsx`, `app/admin/login/page.tsx`, `app/admin/actions.ts` (server actions), `app/auth/callback/route.ts`
- `lib/supabase/auth.ts` (חדש): `requireOwner()` שבודק שהמשתמש המחובר הוא `ADMIN_EMAIL` (משתנה סביבה), אחרת 404 (לא 403: העמוד לא קיים עבור אחרים).
- `lib/rooms/doors.ts` (חדש): `getDoor(slug)` = דריסה מ-`doors` אם קיימת, אחרת `room.json`. **הרישום (`registry.ts`) לא משתנה.**
- `app/[lang]/[room]/page.tsx` ו-`components/house/map.tsx`: להשתמש ב-`getDoor` במקום `room.door` ישירות (שינוי של שורה בכל אחד)
- `proxy.ts`: `/admin` ו-`/auth` מחוץ לניתוב השפות
- `tests/doors.test.ts`: לוגיקת הדריסה כפונקציה טהורה

## התנהגות
- כניסה: שדה מייל אחד. Supabase שולח קישור קסם רק אם המייל שווה ל-`ADMIN_EMAIL`; אחרת מציגים "אם המייל מוכר, נשלח קישור" (לא מגלים).
- דלתות: טבלה, שורה לחדר, שלושה כפתורי רדיו, שדה שלט בשתי שפות, תנאי פתיחה (לכולם / למי שהשאיר חותם / למי שנרשם / מתאריך). שמירה = server action + `revalidatePath('/[lang]', 'layout')`.
- חותמות: רשימת `pending`, לכל אחת "אשר" / "דחה". אישור → `approved` + `revalidateTag('wall')`.
- ללא עיצוב מיוחד: טוקני הבית, טפסים נגישים, וזהו. זה כלי, לא חדר.

## קריטריוני קבלה
- משתמש לא מחובר ב-`/admin` → 404. מייל אחר שנכנס איכשהו → 404.
- שינוי דלת מופיע במפה תוך דקה.
- `npm run check` ירוק.

## אסור
סיסמאות. יותר ממייל אחד מורשה. לוח בקרה "עשיר". להעביר את הרישום ל-DB (room.json נשאר המקור, DB רק דורס).
