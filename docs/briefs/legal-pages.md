# בריף 11: עמודי החוק

**מי:** Opus 5.5. **תלוי ב:** כלום לבנייה. לפתיחה הציבורית: שעה עם עורך דין על `docs/legal/*.md` (דוד מתאם).

## מטרה
`/he/legal/<slug>` ו-`/en/legal/<slug>` לששת המסמכים ב-`docs/legal/`, מקושרים מהפוטר, קריאים בסלולר, מודפסים יפה.

## קבצים שמותר לגעת בהם
- `app/[lang]/legal/[doc]/page.tsx`, `lib/legal/load.ts` (קורא את ה-Markdown בזמן בנייה, מהריפו, לא מרשת)
- `components/house/footer.tsx`: קישורים לנגישות, פרטיות, תקנון
- `docs/legal/*.md`: מותר להוסיף תרגום אנגלי כקובץ אח (`privacy.en.md`), לא לשנות את העברית
- `package.json`: מותר להוסיף `marked` או `remark` (אחד, הקטן) אם אין דרך פשוטה יותר. עדיף: תבנית Markdown מצומצמת ממומשת ידנית (כותרות, פסקאות, רשימות, טבלאות) ב-60 שורות.
- `tests/legal.test.ts`: כל שישה קיימים, לכל אחד כותרת h1 אחת, אין `[לעו"ד]` בגרסה שמתפרסמת (הבדיקה נופלת אם נשאר סימון פתוח ו-`LEGAL_REVIEWED=true`).

## התנהגות
- `proxy.ts` לא משתנה (הנתיב כבר תחת השפה).
- עמוד: כותרת, תאריך עדכון (מהקובץ), תוכן, "נתקלתם במשהו? כתבו לי" עם וואטסאפ.
- `robots`: index. הצהרת נגישות מקושרת מכל עמוד (דרישת התקנות).
- CSS הדפסה: רקע לבן, טקסט שחור, בלי כותרת ופוטר.

## קריטריוני קבלה
- `npm run check` ירוק. Lighthouse נגישות 100 על `/he/legal/accessibility-statement`.
- בניית `main` ביום ההשקה עם `LEGAL_REVIEWED=true` נופלת אם נשאר `[לעו"ד]`.

## אסור
לשנות את תוכן המסמכים (רק עו"ד ודוד). להמציא סעיפים. לפרסם בלי שהבדיקה המשפטית סומנה.
